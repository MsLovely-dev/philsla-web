# Documentation Instructions

These instructions apply under `docs/` in addition to the root `AGENTS.md`.

- Base current-state claims on repository evidence. Label future structures and technologies as proposals.
- Use `TBD` for unresolved decisions rather than selecting a technology or inventing a requirement.
- Preserve existing business documents. Resolve conflicts by identifying the authoritative source and recording the decision; do not silently rewrite business intent.
- Keep relative links valid and use repository-relative paths in examples.
- Update architecture documents and ADRs when boundaries or technology decisions change.
- Update API documentation when endpoint contracts change and business documents when approved behavior changes.
- Do not include real personal data, credentials, assessment content, or sensitive operational details in examples.
- Record the commands actually run; never claim validation passed based on assumption.
