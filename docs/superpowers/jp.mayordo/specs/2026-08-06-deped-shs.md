## Reality check (evidence, not assumption — 2026-08-06)

The Build Plan describes DepEd SHS as *"Not started"* and says to *"wire `DepEdSHSListMaintenance.tsx` (or equivalent) to real backend CRUD."* Against the current code that premise is **stale — the wiring already exists**:

- The screen is `frontend/src/pages/admin/maintenance/SchoolsListMaintenance.tsx` (the "or equivalent"); it is already wired to `schoolService` with real CRUD, `ServiceResult` handling, `error`/`isSaving` states, region dropdown, auto-generated `SCH-#####` code, and a `ConfirmationDialog` delete — the exact Universities pattern.
- Backend `apps/schools` (models, serializers, role-guarded CRUD views, audit, `seed_schools`, tests) shipped in PR #44 and mounts at `/api/v1/schools/`. `apps.schools` tests are green (5/5).
- `frontend/src/services/backendSchoolService.ts` (Backend + Mock + factory) and `backendSchoolService.test.ts` exist and pass. Route `/admin/maintenance/schools` is registered and covered by `routes.test.tsx`.

So the CRUD-wiring deliverable is effectively **already done**. To make DepEd SHS genuinely demo-ready and match the deliverables the Universities slice has, the remaining gap is **frontend test coverage of the screen**, which today is missing for Schools:

## Scope

**In scope (demo-ready)**
- Verify the shipped Schools slice end to end (backend tests, service test, screen renders + does CRUD in both service modes).
- Add `frontend/src/pages/admin/maintenance/SchoolsListMaintenance.test.tsx` — Vitest + Testing Library, asserting the **real** screen ↔ service contract (mount/list, empty state, create round-trip, backend validation error keeps modal open, delete via `ConfirmationDialog`).

**Out of scope (per Build Plan's "demo-ready, not 100%")**
- Any change to `apps/schools`, `backendSchoolService.ts`, or `SchoolsListMaintenance.tsx` behaviour/layout.
- The **two-live-university-backends** duplication (`apps.universities` vs. `apps.configuration` admin registry) and the orphaned/broken `UniversitiesListMaintenance.test.tsx`. Real, but a **separate concern tracked as tech debt** — not this story, and not on the demo path.
